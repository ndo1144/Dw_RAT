# RATTOPIA (3매치 퍼즐 · 턴제 전투)

학원 팀 프로젝트 · Unity, C#
3매치 퍼즐과 턴제 전투를 결합한 구조로, 퍼즐 결과가 전투로 이어지는 흐름을 직접 설계·구현했습니다.

---

## 🎮 게임 개요

퍼즐 매칭으로 공격/방어 블록을 조합해 전투를 진행하는 게임입니다. 몬스터를 처치하면 보상 선택 화면으로 넘어가고, 다시 다음 퍼즐로 이어지는 순환 구조를 가지고 있습니다.

## 👥 팀 구성 및 담당 범위

| 담당자 | 영역 |
|---|---|
| **본인** | 퍼즐 시스템(매칭, 폭탄 콤보), 전투 시스템(턴 흐름, 몬스터 스폰, 상점/경제) |
| 팀원 | 기획, 맵/노드 연출, 스토리 연출, 씬 이동, 컷신, 대화 시스템 |

> 아래 "문제 해결 사례"는 모두 본인이 담당한 퍼즐·전투 시스템 범위 내에서 직접 설계·구현한 부분입니다. 맵/스토리/대화/씬 전환 등 팀원 담당 영역은 다루지 않습니다.

## 🛠 문제 해결 사례 (본인 담당 — 퍼즐·전투 시스템)

### 1. 폭탄 콤보 — 이중 실행 & 상태 플래그 충돌 (경쟁 상태 해결)

**문제**: 폭탄 실행 로직이 (1) 클릭 입력, (2) 폭탄 변환 연출 코루틴 종료 시점, 두 경로에서 각각 호출되는 구조였습니다. 두 경로가 `isProcessing`(처리 중 잠금 플래그) 같은 동일한 상태 변수를 서로 다른 타이밍에 켜고 꺼서, 한쪽이 잠금을 풀어버린 틈에 다른 쪽이 실행되는 등 실행 순서가 보장되지 않는 경쟁 상태(race condition)가 발생했습니다.

**해결**: 폭발 로직 전체를 단일 코루틴 안에 통합하고, 외부(클릭 입력이든 변환 연출이든)에서는 그 코루틴을 시작만 하도록 구조를 바꿨습니다. 모든 처리가 하나의 흐름 안에서 순차적으로 일어나기 때문에 플래그 충돌이 구조적으로 사라졌습니다.

### 2. 턴 경계를 넘는 폭탄 상태 유지

**문제**: 폭탄 여러 개가 겹쳐 순차 발동되는 도중 이동 횟수가 소진되어 턴이 끝나버리는 경우가 있었습니다.

**해결**: 잔여 폭탄 개수를 개별 블록이 아니라 퍼즐 전체 상태를 관리하는 `Match3Manager`의 멤버 필드(`bombCount`)에 저장해, 턴이 전환돼도 값이 초기화되지 않도록 했습니다. 턴 흐름을 담당하는 `CombatManager`의 `StartPlayerTurn()`과 정산 UI 종료 시점, 두 곳에서 `bombCount > 0`인지 검사해 남아있으면 `ResumeBombMode()`로 폭탄 모드를 재개시킵니다. 이동 횟수 소모 시점도 별도 처리하지 않고 기존 매칭 정산 코루틴을 그대로 타고 내려가 `CombatManager.OnMoveCompleted`에서 한 곳에서만 증가하도록 통일했습니다.

### 3. 풀피 아이템 낭비 방지 & 아이콘 Fallback

**문제**: 체력이 가득 찼을 때도 회복 아이템을 사용할 수 있어 아이템이 낭비됐고, 강화 아이템(300번대)의 아이콘 리소스가 누락되면 에러가 발생했습니다.

**해결**: `EconomyManager`의 데이터를 참조해 현재 체력이 최대치면 회복 아이템 클릭을 거부하도록 안전장치를 추가했습니다. 아이콘의 경우 300번대(강화) 아이템 이미지가 없으면 원본(100번대) 아이템 아이콘을 자동으로 불러오는 Fallback 시스템을 구축해 방어적으로 처리했습니다.

### 4. 데미지 팝업 & 아이템 툴팁 UI 안정화

**문제**: 몬스터 피격 시 나타나는 데미지 팝업의 위치/크기가 어색했고, 아이템 툴팁이 다른 아이템 UI에 가려 보이지 않는 문제가 있었습니다.

**해결**: `DamagePopup`의 생성 위치와 크기를 조정해 가독성을 높이고, `UI_Tooltip`의 레이어링 순서를 조정해 다른 아이템 위에 항상 표시되도록 수정했습니다.
